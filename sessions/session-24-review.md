## Method controls used

  `git diff ... -- ':(exclude)sessions' ':(exclude)prompts' ...` (excludes with no
  positive pathspec) returns empty on git 2.50.1 (verified: exit 0, zero files).
  To honor intent (all delivery minus builder-narrative paths) the pass used the
  equivalent `git diff <base> HEAD --stat -- .` + `git diff <base> HEAD -- <file>`
  per file, and confirmed excluded paths carry no delivery: `sessions/*` is untracked,
  `prompts/24-task-docs-nav-groups.md` is the contract itself, `design-reference/nav-groups-mock.html`
  is untracked (correctly uncommitted). Commit granularity checked via
  `git show --stat` (process constraint only; no content outside diff consumed).
- Procedure per `reviewer/SKILL.md`: numbered every requirement-bearing section
  (Goal, Acceptance 1–9, Session constraints), hunted a function/hunk/test per

## Adversarial sweep

- Weak-proxy gate: `verify-session-24.sh` `no-badge-vocabulary` wears the Acceptance 8(b) slot but asserts the negation. Contract: "every README LOCKED chart has badge data true". Script: `if ((c)[locked|trio|inFlight] !== undefined) FAIL` + `if badge vocabulary in App.tsx/index.css/generator/spec → FAIL`. Passes iff nothing badge-like was built. Trivially true on an empty implementation.
- Prose-only behavior: `locked`/`trio`/`in flight` exist only in shell comments (`no status badges`, `lock state is internal`, `deliberately not carried over`) — zero generator fields, zero renderer elements, zero styles.
- Delta by assertion: demo `record "no-badges" PASS` on `CLEAN` (absence) presented as falsifiable proof of a presence requirement.
- Honesty theater risk: demo footer `a green demo is evidence, not a passing delivery` is candid about demo≠proof, but the verify script's header (`Proves: ... zero status badges`) redefines the story as "no badges" while the contract story is "grouped nav + badges" — the headline re-scope is in the gate files, not the demo disclaimer.
- S15 update claim: verify runs `qa-catalog-runs` but the diff contains no update to that suite for `data-group`/`nav-group` DOM; a green run on an un-updated suite would mean it never saw the new DOM.

## Fakest green

`scripts/verify-session-24.sh` → `run_check "no-badge-vocabulary"` standing in for Acceptance 8(b). The contract demands a generated-vs-README consistency check that goes red when a README `### LOCKED:` chart lacks badge data; the script instead goes red when badge data *exists* (`FAIL: generated chart carries badge field`, `FAIL: badge vocabulary in App.tsx...`) and prints `OK: 20 grouped rows, zero badge vocabulary`. It is green precisely because R-A4/R-A5 were never built, and its greenness is then cited as proof the badge story passed. `qa-nav-groups.mjs:check("no-badges", badgeCount===0)` and `demo-session-24.sh:record "no-badges" PASS on CLEAN` are the same inversion in test and demo form.

## Overall verdict

The delivery is one narrow slice (six-group collapsible nav) presented as the whole (grouped nav + generated mudra badges). Grouping, collapse/persist/auto-expand, counts, glyphs, and process hygiene are real; the entire badge half of the story — `locked` derivation from README, `trio`/`in flight` fields, badge rendering and styles, and the README-consistency gate — was silently re-scoped to "zero badges" with gates rewritten to enforce absence.

**Verdict:** REJECT
