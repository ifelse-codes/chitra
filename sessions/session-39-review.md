the expected verdict, what a prior pass had found, or what had been changed since.

**A process failure worth recording, because it was caught by the auditor rather than by me:** on
pass 4 I dispatched the reviewer **before** writing its input file — a `git add -A` had tripped
the 3-file commit cap, the `&&` chain short-circuited, and the file was never created. The
reviewer found the file missing and **declined to emit a verdict at all**, on the grounds that
both ACCEPT and REJECT would be fabricated. That is the correct behaviour of an auditor, and it
is the reason this gate is worth having.

**Pass 2 was run on a defective input — mine, not the auditor's.** I copied
`verify-closeout.sh`'s exclusion list (which exists for *hash stability*) into the review input,
which hid all six `.ai/` files from the auditor. It therefore reported R3's `.ai/` half as
undelivered when it had been. Pass 3 fixed the input; the underlying charge — *no guard covered
`.ai/`* — was true and was fixed.

## The fakest green (each pass named one; all were real)

1. **Pass 1 — `no-false-deprecation-claim` scoped to three files**, none of them the shipped docs
   app. A migration banner on the live site would have shipped on a green board. *The guard for
   the honesty requirement did not cover the honesty surface.*
2. **Pass 1 — `hero-pill-matches-version` was a hardcoded literal** while its comment claimed it
   "pins it to the manifest". A comment asserting a property the code lacks.
3. **Pass 1 — two fabricated `WORKS` rows** in the demo's summary table, printing green while the
   check above printed a red cross.
4. **Pass 2 — `no-rename-notice-shipped` matched phrasings, not absence.** It went green on
   `@ifelse.codes/core → @ifelse.codes/chitra`, `is now`, and `Update your imports`. Replaced with
   a zero-occurrence rule, which cannot be defeated by the next phrasing.
5. **Pass 3 — `mcp-server-still-not-built` evaded `server-mcp.ts`**; `no-npm-secret-in-ci` read one
   of two workflows; `live-ai-files-state-the-present` lacked the `[ -f ]` test its own comment
   taught twice.
6. **Pass 3 — three hand-typed numbers and one overclaim in my own snapshots**: `37/37` quoted in
   five files when the script had 40 checks; `21 files` when the delivery was 27; and `STATE.md`
   saying the hero pill "is now *derived* from the manifest" when the *pill* is a JSX literal and
   only the *check* derives. **This was the demo's fabricated-`WORKS` defect, re-committed as prose.**
   Fixed, and `ai-docs-quote-real-score` now makes a hand-maintained score fail the gate.

## Accepted limitations (not defects, and not fixable from this repo)

- **Unattended publishing is configured, not demonstrated.** npm's trusted-publisher API needs a
  session token, so no check can read the config. The evidence is the outcome, and the outcome has
  not happened yet. A real `0.4.0` through CI would close it.
- **R6's "unattended" is unmet for `0.3.0` and always will be** — npm keeps the trusted-publisher
  config inside a package's own settings page, and a package that does not exist has no settings
  page. Structural, disclosed, and now permanent knowledge in `KNOWLEDGE.md`.
- Commit granularity, `VAJRA_ALLOW_COMMIT`, and push-before-merge are invisible in a squashed diff.
